# Learning Journal

The journal is the heart of this repo: it turns "following a plan" into a public, honest learning record.

## Why journal in public

- **Accountability:** a public log keeps you moving even on unmotivated weeks.
- **English practice:** writing technical entries in English builds the exact vocabulary you'll need for docs, READMEs, and overseas work.
- **Blog fuel:** every entry is a draft for a dev.to / Zhihu post. Month-end, pick one entry and expand it.
- **Debugging memory:** "what did I try, what broke, what fixed it" is the most reusable knowledge you'll produce.

## Rules (keep them light)

1. **One file per week:** `journal/YYYY-MM-weekN.md` (e.g. `2026-09-w2.md`).
2. **Write in English if you can.** Chinese glosses are welcome. Mistakes are fine — this is a log, not an essay.
3. **10 minutes minimum, 30 maximum.** Short and honest beats long and polished.
4. **Always include a "stuck" section.** It's where the real learning is.

## Template

Copy [`template.md`](template.md) for each week.

## Suggested structure

| Section | What to write |
|---|---|
| Focus | This week's phase/weeks and goal |
| Learned | 3–5 bullets: commands, concepts, "aha" moments |
| Hands-on | What you built/ran; paste key output |
| Errors & fixes | What broke, what you tried, what fixed it |
| English corner | New words/phrases + one sentence using each |
| Next week | 1–3 concrete actions |
| Blog idea? | One line: possible dev.to / Zhihu angle |

---

## Repository rule

Keep this repo small and text-first (markdown, configs, small scripts). Large binaries and datasets live elsewhere — journals stay light so the repo stays fast and easy to review.
