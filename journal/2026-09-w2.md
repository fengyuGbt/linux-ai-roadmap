# Week 2 — Permissions, Users, and a Dead Upstream Source

> Date range: 2026-09-20 ・ Phase: Phase 1 / Week 2 ・ Status: ✅ done

## Focus
Understand the permission model (who can do what, and who owns what), users & groups, and package management — with a real fight against a tool whose default download source had silently died.

## Learned
- **The 10-char permission string:** `-rw-r--r--` = type bit (`-` file / `d` dir) + 3 triples (owner / group / other). Each triple is `r w x` in fixed order.
- **Numeric permissions:** `r=4, w=2, x=1`, add them up → `644` = rw- r-- r--, `755` = owner full / group+other read-execute, `600` = owner only, `700` = owner full, nobody else.
- **Symbolic mode:** `chmod u+x` (add owner execute), `chmod go-w` (remove group/other write) — same thing, different spelling.
- **Directory permissions:** `x` = *enter* the directory, `r` = *list* names, `w` = *create/delete* entries. A `chmod 700` directory is a private vault — even listing it fails without permission.
- **`chmod` vs `chown`:** `chmod` changes the permission bits; `chown user:group` changes *ownership*. `chown` needs `sudo` — giving files away is a root privilege.
- **Users & groups:** uid=1000 = first normal user (root is 0, system services 1–999); each user gets a same-named primary group. `sudo` group = the admin switch; `adm` = read `/var/log`; `docker` ≈ root (group can control the daemon).
- **Group philosophy:** permissions attach to *groups*, not individuals — add a person to a group and they inherit its powers.
- **`sudo` & `apt`:** `sudo` = superuser do (install writes to system dirs); `apt update` refreshes the *package index* (the catalogue), `apt install` actually installs. `upgrade` updates what's already installed.
- **man vs tldr:** man = complete authoritative manual; tldr = 8 copy-paste examples. Complementary: tldr first to move, man to understand.

## Hands-on
Permissions on the lab files, ownership transfer, user introspection, package install:

```bash
echo 'echo "hello from lab"' > scripts/hello.sh
chmod 755 scripts/hello.sh ; ls -l scripts/hello.sh   # -rwxr-xr-x
chmod u+x scripts/hello.sh                             # symbolic mode
chmod go-w data/world-cities.csv

touch .secret_test ; chmod 600 .secret_test            # owner only
mkdir private ; chmod 700 ~/lab/private                # private vault dir

id        # uid=1000(erp) gid=1000(erp) groups=erp,adm,cdrom,sudo,dip,plugdev,users,docker
groups

sudo chown root:root world-cities.csv ; ls -l          # owner became root
sudo chown erp:erp world-cities.csv ; ls -l            # back to erp:erp
```

`sudo apt install -y tldr` → `tldr find` worked after the fix below.

## Meta: what I learned about learning
- **"Not a valid archive" almost always means you downloaded the wrong content** (an HTML page, a 404, a redirect). Check `curl -I` + `file` before debugging the tool.
- **A tool's default upstream can die silently.** Manual cache population (`~/.local/share/<tool>/`) is a universal escape hatch.
- Chaining tiny permission operations is the fastest way to *feel* the model — and to hit real mistakes like `chmod` on a file instead of a dir.
