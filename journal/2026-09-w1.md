# Week 1 — Filesystem, Data Download, and Two Real Pits

> Date range: 2026-09-19 ・ Phase: Phase 1 / Week 1 ・ Status: ✅ done

## Focus
Explore the Linux filesystem layout, build the `~/lab` workspace, download a real dataset, and inspect it with text tools — while learning why "plain-text tools" are not enough for structured data.

## Learned
- **Filesystem map:** `/etc` = config files, `/var/log` = logs, `/tmp` = scratch space, `/` = everything's root. `df -h` shows disk usage; `du -sh ~/* | sort -rh | head -10` finds the biggest directories (my `micromamba` env: 3.4G — a data-science install eats disk fast).
- **Brace expansion:** `mkdir -p ~/lab/{data,scripts,models,logs}` creates 4 dirs in one command — bash syntax sugar, very common in real scripts.
- **`curl` flags:** `-x <proxy>` route through a proxy, `-L` follow redirects, `-o` save to a file (vs `-O` = use remote filename). My dataset URL returned HTTP 200 directly, but `-L` is the safety habit for CDN links.
- **Data reality check:** `world-cities.csv` has **4 columns** (`name,country,subcountry,geonameid`), **34128** data rows, **244** unique countries, **2122** Chinese cities.
- **Tool tiers:** `grep`/`cut` are text tools (match/split characters); structured data (CSV/JSON) needs a *parser* (`csv.DictReader`, later pandas). Quotes in CSV are *syntax*, not *data*.
- **Public-repo hygiene:** never commit real IPs, proxy addresses, tokens or emails — use placeholders and tell readers how to find their own values.

## Hands-on
Explored the system, built the lab, downloaded and inspected the data:

```bash
ls / ; ls /etc ; ls /var/log ; ls /tmp
df -h                                   # disk: 928G free on /
du -sh ~/* 2>/dev/null | sort -rh | head -10

mkdir -p ~/lab/{data,scripts,models,logs}
tree ~/lab

cd ~/lab/data
curl -x <your-proxy> -L -o world-cities.csv \
     https://raw.githubusercontent.com/datasets/world-cities/master/data/world-cities.csv
# 1.3MB in ~5s via proxy

head -5 world-cities.csv                 # header: name,country,subcountry,geonameid
wc -l world-cities.csv                   # 34129 lines (incl. header)
grep -i "china" world-cities.csv | head -5
cut -d, -f2 world-cities.csv | sort -u | head
```

Correct column analysis (Python stdlib, zero install):

```python
import csv
rows = list(csv.DictReader(open('world-cities.csv')))
print(len(rows))                            # 34128
print(len({r['country'] for r in rows}))    # 244
print(sum(1 for r in rows if r['country']=='China'))  # 2122
```

## Errors & fixes
| Error | What I tried | What actually fixed it |
|---|---|---|
| `head 10` → `cannot open '10'` | Dropped the dash | `head -10`; bare words are filenames, options need `-` → archived as [pitfalls/001](../pitfalls/001-argument-without-dash.md) |
| `cut -d, -f5` returned numbers; `-f2` showed `"Bolivia`, `Saitama"` | Assumed plain comma separation | The CSV quotes fields containing commas (RFC 4180); `cut` splits on every comma. Used `csv.DictReader` → archived as [pitfalls/002](../pitfalls/002-csv-quotes-cut.md) |
| `grep -i "china"` matched `Chinatown,Canada` | — | grep matches whole lines, not columns; column filtering needs a parser |
| Direct download to github.com timed out | — | Route through proxy with `-x <your-proxy>` |
