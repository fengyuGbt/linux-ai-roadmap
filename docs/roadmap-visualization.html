Linux × AI — 12-Week Learning Roadmap

An AI-first path from zero to running, serving, and deploying local LLM & data workflows on Ubuntu 24.04 LTS. Every phase ties a Linux concept to a real AI/data workflow, and every project is something you can publish.

Phase 1–2: Linux core Phase 3: Python data env Phase 4: Local AI/LLM stack Phase 5: Deploy & ops Ongoing habits
Phase 0Day 0

Environment setup

Goal: a working Ubuntu 24.04 shell (WSL2 / VM / VPS) + Git configured.

Actionsapt update & upgrade ・ Git identity ・ SSH key ・ htop / tmux
First commandspwd ・ ls -lh ・ cd — and read their man pages
Project✓ Terminal works, env checklist passes
Phase 1Weeks 1–2

Linux fundamentals

Goal: own files, paths, permissions, users and package management — the daily toolbox of an AI engineer.

Week 1Filesystem layout ・ find / du / df ・ less / grep / vim basics
Week 2chmod / chown ・ sudo & users ・ apt ・ man / tldr
AI tie-inDataset file & permission hygiene; where models, data and logs live
Project~/lab workspace + a real dataset inspected by hand
Phase 2Weeks 3–4

Shell & automation

Goal: pipelines, scripts, services, scheduled jobs, SSH and Git from the terminal.

Week 3Pipes & redirection ・ sed / awk / sort / xargs ・ bash scripting ・ nohup / htop
Week 4systemd units ・ cron / timers ・ ssh-keygen / rsync ・ git push / pull
AI tie-inAutomating data pipelines; keeping long-running jobs alive
Projectprocess_dataset.sh + scheduled backup via systemd timer
Phase 3Weeks 5–6

Python data environment on Linux

Goal: clean, reproducible Python + data stack — the "works on my laptop" failure mode ends here.

Week 5venv / uv ・ PATH & env vars ・ Jupyter headless ・ pathlib
Week 6parquet vs csv ・ git-lfs ・ Docker basics (run / ps / volumes)
AI tie-inFirst contact with containers — the standard delivery format for AI apps
ProjectData-analysis script + tiny Dockerfile run in a container
Phase 4Weeks 7–9

Local AI / LLM stack

Goal: run and serve real models — GPU acceleration (or a sensible CPU path), local LLMs, and a working RAG system.

Week 7nvidia-smi / nvtop ・ CUDA toolkit ・ torch.cuda check (CPU fallback documented)
Week 8Ollama pull / run ・ quantization (q4 / q8, GGUF) ・ REST API via curl
Week 9Hugging Face ・ embeddings ・ FAISS / Chroma ・ RAG: retrieve → augment → generate
AI tie-inThis is the phase where Linux becomes your AI workstation
Capstone projectrag-demo: answer questions from your own documents with sources
Phase 5Weeks 10–12

Deployment & operations

Goal: ship an AI service that stays up — from "can run models" to "can run a model-backed product".

Week 10FastAPI + uvicorn ・ systemd service ・ journalctl
Week 11Cloud Ubuntu server ・ SSH hardening + fail2ban ・ ufw ・ Nginx reverse proxy
Week 12htop / glances ・ rsync backups ・ GitHub Actions CI ・ auto-deploy
FinaleRAG service live on a public URL + monitoring + CI
OngoingAfter week 12
